# 证明器反馈指标、阈值与 Solver Profile

本文按当前代码整理：求解器失败后实际用到的信号、相对化门槛、repair hint 判定，以及 Vampire / CVC5（含 CVC4）的 named profile 与命令行选项。常数以 `solver_relative_metrics.py`、`vampire_runner.py`、`cvc5_runner.py`、`solver_routing.py` 为准。

证明成功条件始终只认 `unsat`。下面所有指标只影响**下一轮引理形状、prompt 族和 profile 排序**，不改变有效性判定。

闭环讲解（各通道何时写入、progress 与 repair 细 kind 为何不是同一把尺子、以后改 cand vs baseline 时对照什么）：[当前反馈闭环与指标设计.md](当前反馈闭环与指标设计.md)。

---

## 1. 反馈用在哪里

一次失败 run 会留下状态、统计、（Vampire）归纳焦点、（CVC5）difficulty。它们分成三路：

| 去向 | 作用 |
|------|------|
| **repair hint** | 单次 run 内部的 mix / 焦点 / 难度 → 告诉 LLM 缺哪类引理 |
| **progress score** | 加入候选引理后的 3s sidecar，相对 control（或 3s baseline）是否「不那么卡住」 |
| **profile utility** | 2s probe 之间比相对活动率，只用于排序候选 profile |

progress 与 hint **不要混用**：60s 正式 prove 的 difficulty / induction 写 hint；progress 只比同协议的 3s sidecar。

## 2. 共用相对化原语

实现：`solver_relative_metrics.py`。所有「有没有进展」的门都作用在比率或对数增量上，而不是 `INST > 50` 这种绝对计数。

### 2.1 原语

| 名称 | 定义 | 讲解 |
|------|------|------|
| `log_gain(cand, ref)` | \(\log(1+\mathrm{cand})-\log(1+\mathrm{ref})\) | 对数增量，\(0\to 3\) 不会爆成无穷大，大计数 \(10000\to 10040\) 几乎为 0。 |
| `activity_rate(count, elapsed)` | `count / max(elapsed, 0.2)` | 把计数换成**每秒率**，3s sidecar 和提前结束的 run 才能比。分母下限 0.2s，避免除零。 |
| `is_relative_gain` | 见下节门槛 | 判定 cand 相对 ref 是否算一次真正增益。 |
| `gain_score(cand, ref, cap)` | \(\min(\mathrm{log\_gain}/\ln 2,\;\mathrm{cap})\) | 把增益映射成分数：大约 **翻倍 → 1 分**，再封顶。 |
| `pct_label` | 相对增量的整数百分比 | 写进 prompt，例如 `more_demodulations(+125%)`。rate 用 \(\varepsilon\) 作分母，不用 `max(ref,1)`。 |
| `in_problem_hard_cutoff` | 本题**正** difficulty 分数的分位数 | 「难」是相对这道题，不是全局 `≥3`。 |
| `is_relative_drop(old, new)` | \((\mathrm{old}-\mathrm{new})/\mathrm{old} \ge 0.20\) | difficulty 下降是否算进展。 |
| `gate_overshoot(value, threshold)` | 越过 mix 门的程度，压到 \([0,1]\) | 给 hint 一个 `strength`，两类 prompt 族同时触发时当抽样权重。 |

### 2.2 增益与爆炸门槛

| 常数 | 默认 | 用在 | 讲解 |
|------|------|------|------|
| `LOG_GAIN_MIN` | \(\ln 1.20\approx 0.182\) | 高流量计数（demod、INST、conjecture、子句） | 大约 **+20%** log-gain 才算进展。挡住「几乎没变」的噪声。 |
| `LOG_GAIN_MIN_RARE` | \(\ln 1.10\approx 0.095\) | 稀有事件（skolem、归纳应用、eq-taut） | 大约 **+10%**。允许 \(0\to 1\)，但 \(100\to 101\) 过不了。 |
| `NOISE_FRAC` | `0.02` | 高流量的绝对地板 | 增量必须 \(> 2\%\times\mathrm{ref}\)。**计数**还要至少多 1 次；**速率**不加「至少 +1」——否则 `0.4/s → 0.9/s` 会被误杀。 |
| `DIFFICULTY_REL_DROP` | `0.20` | CVC5 目标/公理难度 | 相对下降 ≥ **20%** 才记 drop。`10→8` 与 `3→2` 都算，`3→2` 不再要求「必须降满 2 分」。 |
| `EXPLOSION_LOG_GAIN` | \(\ln 1.50\approx 0.405\) | 搜索爆炸 | 体积大约 **+50%** 且没有对应产出，才扣分。 |
| `HARD_AXIOM_PERCENTILE` | `0.50` | CVC5 hard axioms | 取本题正分数的**中位数及以上**，最多 4 条。单独一条 `difficulty=1` 也会进列表。 |

`is_relative_gain` 的完整规则：

- 高流量（`rare=False`）：cand > ref，且增量超过噪声地板，且 log-gain ≥ `LOG_GAIN_MIN`。
- 稀有（`rare=True`）：只要求 log-gain ≥ `LOG_GAIN_MIN_RARE`，不做 2% 地板。

## 3. 求解状态（两边共用语义）

| status | 含义 |
|--------|------|
| `unsat` | 找到反驳，目标得证。唯一成功条件。 |
| `sat` | 找到模型（对「否定目标」来说通常表示目标不成立或编码反了）。 |
| `timeout` | 时间用尽，**不表示**公式为假。 |
| `unknown` | 无法分类。 |
| `incomplete` | Vampire：当前策略声明找不到反驳（仍可能换策略证出）。 |
| `error` | 输入/二进制错误。Vampire 匹配 `User error:`（不是错误的 `"user:"` 子串）。 |

progress：`proved` → 分 100；`error` → 分 −10，信号 `solver_error`。

## 4. Vampire 反馈

### 4.1 采集到的原始统计

来自 `--statistics full` 的最后一块（portfolio 会打很多块，取每个 key 的最后一次）。

| 原始 key | 讲解 |
|----------|------|
| `Generated clauses` | 搜索生成的子句总数。体积代理；单独变大不叫进展。 |
| `Final active clauses` | 参与推理的活跃子句。 |
| `Final passive clauses` | 还没被选中的被动子句。被动比下降 ≈ 搜索更聚焦。 |
| `Fw demodulations` / `Bw demodulations` | 前/后向解调，等式改写次数。 |
| `Fw demodulations to eq. taut.` | 解调出等式重言式。比裸 superposition 更像「改写出了东西」。 |
| `Forward superposition` / `Backward superposition` | 等式叠加。体积大、产品少时像搜索爆炸。 |
| `StructuralInduction` | 结构归纳图式被用到的次数。 |
| `InductionApplications` | 归纳应用总次数。 |
| `GeneralizedInductionApplications` | 一般化归纳。 |
| `IntegerInfiniteIntervalInduction` | 整数无穷区间归纳。ADT 题上通常为 0。 |
| `IntegerFiniteIntervalInduction` | 整数有限区间归纳。 |
| `MaxInductionDepth` | 本次达到的最大归纳深度（小整数，不用 log-gain）。 |

归纳活动在代码里合成两组：

- **结构类** = `InductionApplications` + `StructuralInduction` + `GeneralizedInductionApplications`
- **整数类** = 两个 `Integer*IntervalInduction`
- **总归纳** `ind` = 两组之和；**解调** `dem` = Fw+Bw demodulations

### 4.2 归纳焦点（`--show_induction on`）

| 信号 | 上限 | 讲解 |
|------|------|------|
| `[Induction] process <literal> in N.` | 去重后 8 条 | Vampire 正在对哪些文字/项做归纳。写进 hint 的 `induction_focus`（prompt 里最多 6 条）。 |
| `[Induction] formula k. <schema>` | 去重后 4 条，再压缩到 2 条 schema | 实际尝试的归纳公式。优先与 focus 词重叠、或含 `=>` 的步进式。截断到 180 字符。 |

没有焦点时不写 `induction_stuck`。

### 4.3 Unsat core

有用性**不再**开 `--output_mode ucore`（与原文一致：证出则整组 \(C\) 都作为子目标）。失败路径走 `--statistics full` + `--show_induction`，用这次 60s \(A\land C\to P\) 写 mix 细 kind。`parse_ucore_lemma_names` 仍留在 runner 里，但有用性入口不再调用。

### 4.4 Progress 信号与打分

比较对象：候选 3s vs control 3s（没有 control 则 vs baseline）。用每秒率。

| 信号 | 门槛 | 加分 | 讲解 |
|------|------|------|------|
| `more_demodulations(+N%)` | demod+eq-taut 率过 `is_relative_gain`（高流量） | `gain_score`，帽 2.5 | 改写家族合成**一条**信号，不再把 demod 和 taut 各算一次 strong。 |
| `more_induction_activity(+N%)` | 结构+整数归纳率，`rare=True` | 帽 2.0 | 整数归纳与结构归纳同一通道，整数题不再「进度面是瞎的」。 |
| `lower_passive_ratio` | 被动/生成 \(< 0.7\times\) baseline，且（有 control 时）\(< 0.9\times\) control；生成子句 ≥ 1 | +1.0 | 搜索更聚焦。不再要求 `Generated clauses > 100`。 |
| `search_explosion(+N%)` | 子句率或 superposition 率 log-gain ≥ \(\ln 1.5\)，且上面三条产出都没有 | 扣最多 1.5 | 只灌子句、没有改写/归纳/聚焦。 |
| `weak_single_signal` | `strong < 2` 且没有归纳信号 | 正分 × **0.35** | 单弱通道打折。归纳单独出现不算弱。 |
| `no_measurable_progress` | timeout/incomplete/unknown 且没有任何信号 | 0 | 明确告诉 LLM 这次没测到进展。 |
| `proved_goal` / `solver_error` | 见 §3 | 100 / −10 | — |

写入 prompt 的 progress lemma：sidecar 分 ≥ **`_PROGRESS_SCORE_THRESHOLD = 0.5`**。最多诊断 3 条非平凡 singleton，prompt 最多保留 6 条。

### 4.5 Repair hint 与 mix 阈值

每条 hint **一个不等式**。可以同时给出，不再 `if/elif` 掐掉另一条。

记 `mix = ind + dem`，`rewrite_per_ind = dem / max(ind, 1)`，`ind_share = ind / mix`。

| hint kind | 条件 | 阈值 | 讲解 |
|-----------|------|------|------|
| `induction_stuck` | 有 focus 或压缩后的 schema | 无数值门；`strength=0.5` | 「卡在这些项上」，不是 mix。提示对 focus 里的构造子写等式桥。 |
| `need_rewrite` | `ind > 0` 且 `dem/ind < 8` | `REWRITE_PER_INDUCTION_MAX = 8` | 归纳已经在动，但解调相对太少。缺能在 IH 下改写的等式引理。 |
| `need_induction_lemma` | `ind_share < 0.15` 且整数归纳不占主导 | `INDUCTION_SHARE_MAX = 0.15` | 归纳占总（归纳+解调）不到 15%。需要更强/更一般的归纳引理。 |
| `need_arithmetic_lemma` | 整数归纳 / 总归纳 ≥ 0.70 | `INTEGER_INDUCTION_SHARE_MIN = 0.70` | 归纳活动几乎全是整数区间归纳。应写递推/单调性/界，不要写 ADT 构造子事实。 |
| `need_directed_rewrite` | superposition / (demod+taut) ≥ 8 | `SUPERPOSITION_PER_REWRITE_MIN = 8` | 等式在叠加但不化简。要 LHS 对准目标子项的定向重写，而不是过宽的量化等式。 |
| `induction_depth_limit` | `MaxInductionDepth ≥ 2`，状态为 timeout/incomplete/unknown，且 `ind > 0` | `MAX_INDUCTION_DEPTH_HINT = 2` | 深度顶格仍证不出，加深搜索没用，要强化/一般化引理。`strength = min(1, depth/4)`。 |
| `timeout` | 状态 timeout **且**上面一条都没有 | — | 兜底：没有可用结构信号时才写。 |

`strength` 来自 `gate_overshoot`：离门槛越远越接近 1，给 prompt 族抽样用。

### 4.6 已解析、但 progress 不再单独计分的量

`Forward/Backward superposition` 不进正分，只进爆炸体积。`Bw demodulations` 并进 rewrite 通道。不要把它们再当成独立证据。

## 5. CVC5 反馈

### 5.1 `--stats` 原始 key 与合成量

| 原始 / 合成 | 讲解 |
|-------------|------|
| `QUANTIFIERS_INST_E_MATCHING` | E-matching 实例化。 |
| `QUANTIFIERS_INST_E_MATCHING_SIMPLE` | 简单 E-matching。与上一行**分别计数**，不再用会双计的正则。 |
| `QUANTIFIERS_INST_CBQI_PROP` / `_CONFLICT` | 反例引导实例化（传播 / 冲突）。冲突项**不**计入 `INST_TOTAL`。 |
| `QUANTIFIERS_SKOLEMIZE` | Skolem 化。归纳/存在量词展开的硬信号。 |
| `QUANTIFIERS_CONJ_GEN_GT_ENUM` / `_SPLIT` | 猜想生成（枚举 / 分裂）。体积代理。 |
| `DATATYPES_INST` / `_SPLIT` / `_UNIF` | 数据类型实例化、分裂、合一。 |
| `DATATYPES_LABEL_EXH` / `_COLLAPSE_SEL` | 解析了，但**不**进 `DT_TOTAL` 和 progress。 |
| **`INST_TOTAL`** | E-matching 两类 + CBQI_PROP。 |
| **`CONJ_TOTAL`** | 两个 conjecture-gen。 |
| **`DT_TOTAL`** | INST + SPLIT + UNIF。 |
| `TOTAL_TIME_MS` | `global::totalTime`，辅助看墙钟。 |

诊断还会开 `-o inst`，解析 `(num-instantiations <公式或qid> N)`，最多 12 条。用于「高难度公理却从未被实例化」。

### 5.2 `get-difficulty`

注入 `(set-option :produce-difficulty true)`（有 `set-logic` 则紧跟其后；没有则插在**首条命令之前**），并在第一条 `(check-sat)` 后跟 `(get-difficulty)`。用括号平衡扫描解析，嵌套 `forall` / `plus` 可以读到。

每项是 `( <断言 s-expr> <非负整数> )`。分数按本题内部分位，不按绝对 `≥3`。

目标项用 proof-goal 块做规范化匹配，禁止子串碰运气（避免高难度否定公理抢在真正目标前面）。

| 派生 | 门槛 | 讲解 |
|------|------|------|
| `hard_axioms` | 正分 ≥ 本题中位数，最多 4 条；排除 proof goal | 这道题里相对最难的公理，写进 prompt。 |
| `goal_fragments` | role=`goal` 的项，最多 2 | 目标本身的难度项。 |
| `rarely_instantiated` | hard axiom 在 `-o inst` 公式迹里计数为 0，最多 3 | 难但没被匹配到；提示写 LHS 能触发它的重写。qid-only 的 inst 迹无法判断，返回空。 |
| 公理从 candidate top 列表**消失** | 也算 drop | 不必同一字符串仍在列表里且分数下降。 |

### 5.3 Progress 信号与打分

同样比每秒率；difficulty 用相对下降。

| 信号 | 门槛 | 加分 | 讲解 |
|------|------|------|------|
| `more_instantiations` 或 `more_conjecture_gen` | `CONJ+INST` 合成通道过高流量增益 | 帽 2.5；按谁 log-gain 更大选标签 | conjecture 与 INST 高度相关，只算 **一条** matching 信号。 |
| `more_skolemize(+N%)` | skolem 率，`rare=True` | \(0.4+\mathrm{gain}\)，帽 2.0 | 归纳/存在展开在动。 |
| `more_datatype_inference(+N%)` | `DT_TOTAL` 率，`rare=True` | 帽 1.5 | ADT 推理更活跃。 |
| `goal_difficulty_drop(old→new,P%)` | 目标难度相对降 ≥ 20% | \(1.5\times\min(\mathrm{drop}/0.5, 1)\) | 降 50% 拿满 1.5。 |
| `axiom_difficulty_drop(xN)` | 至少 1 条公理相对下降或从列表消失 | \(0.75N\)，帽 2.0 | 公理变容易。 |
| `search_explosion`（conj） | conjecture 率 log-gain ≥ \(\ln 1.5\)，且没有 skolem / difficulty / datatype 产出 | 扣最多 1.5 | 只在枚举猜想。 |
| `search_explosion`（inst） | INST 爆炸 **且** conj 也过 `LOG_GAIN_MIN`，同样无产出 | 再扣最多 1.5 | 灌实例化也不算进展。 |
| `weak_single_signal` | `strong < 2` 且没有 skolem、没有目标难度下降 | 正分 × **0.4** | 略宽于 Vampire 的 0.35。 |
| `no_measurable_progress` | 全无信号 | 0 | — |

progress 入选阈值同样是 **0.5**；sidecar 最多 3 条 lemma。

### 5.4 Repair hint 与 mix 阈值

记 `q_activity = CONJ + SKOLEM + INST`。

| hint kind | 条件 | 阈值 | 讲解 |
|-----------|------|------|------|
| `high_difficulty_assertions` | 有 hard axioms 或 goal fragments | 中位数分位，见上 | CVC5 最有特色的结构信号。连接难公理与目标。 |
| `need_stronger_lemma` | `conj > 0` 且 `skolem/conj ≤ 0.05` | `SKOLEM_PER_CONJ_MAX = 0.05` | 猜想生成很多、Skolem/归纳强化很少。缺更强归纳引理。 |
| `need_rewrite` | `skolem > 0` 且 `inst/(skolem+inst) < 0.75` | `INST_OF_MATCHING_MAX = 0.75` | 已经 Skolem 了，但实例化还占不到 matching 活动的 75%。缺能触发 matching 的重写引理。 |
| `timeout` | timeout/unknown 且上面都没有 | — | 兜底。 |

`need_stronger` 与 `need_rewrite` 允许同时给出（无 `elif`）。`priority` 分别为 1 和 2，prompt 里都能看到。

### 5.5 模块里仍定义、当前 mix **不再使用**的常数

避免和旧文档搞混：

| 常数 | 值 | 状态 |
|------|----|------|
| `CONJ_SHARE_MIN` | 0.25 | 旧「conj 份额 ≥ 25%」；现已改成 `skolem/conj ≤ 0.05` |
| `INST_PER_SKOLEM_MAX` | 10 | 旧「inst/skol < 10」绝对比；已换成 `inst/(skol+inst) < 0.75` |
| `SKOLEM_SHARE_MIN` | 0.01 | 旧 skolem 份额门，现用 `skol > 0` |
| Vampire `INDUCTION_SHARE_MIN=0.08`、`INDUCTION_PER_REWRITE_MAX=0.02`、`REWRITE_SHARE_MIN=0.85` | — | 旧 AND 双不等式；现各 hint 只留一个门 |

## 6. 闭环里的其它阈值（不是求解器 stats）

| 名称 | 默认 | 讲解 |
|------|------|------|
| `_PROGRESS_SCORE_THRESHOLD` | `0.5` | sidecar 分低于此不进 `progress_lemmas`。相对评分把「约 2×」映到 1 分，单弱信号打折后常常过不了。 |
| `_MAX_PROGRESS_DIAG_LEMMAS` | `3` | 有用性失败后最多给 3 条非平凡 singleton 做 3s 诊断。 |
| `_DIAGNOSTIC_TIMEOUT` | `3` 秒 | sidecar / 缓存的短诊断。 |
| `_MAX_PROGRESS_LEMMAS` | `6` | prompt 里 progress 条数上限。 |
| `_MAX_SUBGOAL_FAILED_HINTS` | `2` | `subgoal_failed` 单独留窗口；其它 kind **每种只留最新一条**。 |
| 引理过滤超时 | `1` 秒 | 语法/与公理矛盾的短检查。 |
| 初始 prove / 有用性 | `DEFAULT_CVC_TIMEOUT` / `COMBINED_CVC_TIMEOUT` = **60s** | 论文主路径超时。 |
| 任务墙钟 | `TASK_TIMEOUT=1200` | 整题上限。 |
| 递归深度 | `MAX_RECURSION_DEPTH=3` | 义务树最深 3 层。 |
| 每模板 attempt | `MAX_ATTEMPTS_PER_PROMPT=3` | 两个模板共享 2×3 预算。 |
| `NO_HELP_PROMPT_SWITCH` | `2` | 连续两次 empty/invalid/useless 才切换另一 prompt 族。 |
| `_FAMILY_STRENGTH_FLOOR` | `0.05` | 某族 hint 触发但 overshoot=0 时，仍给一点抽样票，避免被当成没出现。 |
| 平凡引理跳过 | `(= t t)`、`(=> P P)`、control 同型 `(forall ((x T)) (= x x))` | 不进 sidecar，避免恒真刷分。 |

hint 窗口：**按 kind 去重留最新**，不再 `existing[-4:]` 按插入序截断。结构类 hint 不会被后面的 `timeout` 挤掉。

## 7. Vampire profiles

论文默认回退：`induction_portfolio`（`--mode portfolio --schedule induction`）。

所有 run 共用：

| 选项 | 值 | 讲解 |
|------|----|------|
| `-t` | `{timeout}s` | 墙钟限制。 |
| `--input_syntax` | `smtlib2` | 读预处理后的 SMT-LIB2。 |
| `--output_mode` | `vampire`（证明）或 `ucore`（有用性剪枝） | ucore 时关 statistics/proof。 |
| `--statistics` | `full` 或 `none` | 反馈需要 full。 |
| `--proof` | 默认 `off` | 不把证明树当反馈。 |
| `--show_induction` | 首次 prove / sidecar 为 `on` | 采集 focus 与 schema。 |

### 7.1 Portfolio schedules（`kind=portfolio`）

命令：`--mode portfolio --schedule <name>`。Vampire 内部再跑一组策略；诊断 sidecar 映射到右列单策略，保证 progress 可比。

| profile | `--schedule` | sidecar 映射 | 讲解 |
|---------|--------------|--------------|------|
| `induction_portfolio` | `induction` | `struct_single` | 论文默认。结构归纳与整数归纳混跑。ADT 与混合题的安全回退。 |
| `struct_induction` | `struct_induction` | `struct_single` | 偏代数数据类型/构造子归纳。纯 ADT 静态分流首选。 |
| `struct_induction_tip` | `struct_induction_tip` | `struct_single` | TIP 风格结构归纳，偏小的 datatype 等式。 |
| `integer_induction` | `integer_induction` | `int_single` | 整数归纳 schedule。纯 Int 题首选。 |
| `smtcomp` | `smtcomp` | `alasca_arith` | SMT-COMP 算术/混合理论。ADT+LIA 时与 portfolio、ALASCA 一起作为候选。 |

### 7.2 单策略 profiles（`kind=vampire`）

命令：`--mode vampire` + 下表 `extra`。`--avatar off` 关掉 AVATAR 分拆，统计更干净、也避免 portfolio 式组合爆炸。

#### `struct_single` — 单策略结构归纳（诊断用）

| 选项 | 值 | 讲解 |
|------|----|------|
| `--induction` | `struct` | 只做结构/构造子归纳。 |
| `--induction_gen` | `on` | 允许生成归纳假设/一般化。 |
| `--induction_on_complex_terms` | `on` | 不只对变量，也对复杂项启动归纳（递归函数应用等）。 |
| `--avatar` | `off` | 关闭子句分拆。 |

#### `int_single` — 单策略整数归纳（诊断用）

| 选项 | 值 | 讲解 |
|------|----|------|
| `--induction` | `int` | 只做整数归纳。 |
| `--induction_gen` | `on` | 同上，生成归纳一般化。 |
| `--avatar` | `off` | 同上。 |

#### `alasca_arith` — ALASCA 风格算术 superposition

本仓库 Vampire **没有**独立 `--alasca` 开关。这是用当前二进制上的相关选项**近似**：

| 选项 | 值 | 讲解 |
|------|----|------|
| `--induction` | `both` | 结构归纳与整数归纳都开。 |
| `--theory_instantiation` | `all` | 理论实例化（常依赖内部 SMT，失败则该 profile 效用为负、自动降权）。 |
| `--unification_with_abstraction` | `interpreted_only` | 带抽象的合一，只对解释符号（算术）做 UWA，减轻解释理论与叠加的冲突。 |
| `--arithmetic_subterm_generalizations` | `cautious` | 谨慎地对算术子项做一般化，便于发现递推/单调性。 |
| `--avatar` | `off` | 同上。 |

实验表述里不要写成「启用了 Vampire `--alasca`」。

### 7.3 静态分流 → 候选顺序

| 理论特征 | 候选（先到后） |
|----------|----------------|
| 纯 ADT | `struct_induction`, `induction_portfolio`, `struct_induction_tip` |
| 纯 Int | `integer_induction`, `alasca_arith`, `smtcomp`, `induction_portfolio` |
| ADT+LIA | `induction_portfolio`, `smtcomp`, `alasca_arith`, `struct_induction` |
| 其它 | `induction_portfolio`, `smtcomp` |

hint 再提升：`need_arithmetic_lemma` → ALASCA / 整数归纳；`need_rewrite` / `induction_stuck` → 结构归纳；`need_induction_lemma` / `induction_depth_limit` → portfolio + 结构归纳；`search_explosion` / `timeout` → 收窄到 `struct_induction` / `struct_single`。论文 `induction_portfolio` 始终留作 fallback。

## 8. CVC5 / CVC4 profiles

论文默认四路并行（先 `unsat` 的赢）：

`cvc5_simple` · `cvc5_inductive` · `cvc5_inductive_no_ematching` · `cvc4_default`

额外三条用于路由，不在论文 portfolio 里。

所有 CVC5 证明命令在采集 stats 时会加 `--stats` 和 `--tlimit-per={timeout×1000}`（毫秒）。超时仍能吐计数；`get-difficulty` 依赖 `produce-difficulty`。CVC4 **没有** `--stats` / difficulty，probe 会跳过它。

sidecar 诊断：若当前 profile 是 CVC5 就用它自己；CVC4 映射到 `cvc5_inductive`（CVC4 做不了 difficulty）。

### 8.1 共用与论文四路

| 选项 | 出现在 | 讲解 |
|------|--------|------|
| `--lang=smt2` | 全部 CVC5 | SMT-LIB2。 |
| `--lang=smt2.6` | 仅 CVC4 | CVC4 的 SMT-LIB 方言。 |
| `--full-saturate-quant` | 全部 | 量词饱和直到超时，而不是早停。归纳题需要尽量实例化。 |
| `--quant-ind` | 除 `cvc5_simple` 外 | 打开量词归纳（结构/整数等，具体哪种由后面的开关决定）。 |
| `--conjecture-gen` | inductive / no-ematching / cvc4 / controlled | 自动生成辅助猜想。体积大时可能爆炸，于是有 controlled 与 no-ematching。 |
| `--tlimit-per` | 采集 stats 时 | **每个** check-sat 的毫秒上限，保证超时仍有 `--stats`。 |
| `--stats` | 反馈路径 | 见 §5.1。 |
| `-o inst` | 诊断 | 每条量化公式的实例化次数。 |
| `--quant-cf` | 仅 CVC4 | CVC4 的 quantifier conflict find（冲突驱动实例化）。 |

#### `cvc5_simple`

```text
--lang=smt2 --full-saturate-quant
```

无显式归纳、无猜想生成。靠饱和实例化。适合已经接近可证、或归纳开关反而添乱时。

#### `cvc5_inductive`（论文主策略 / 混合题首选）

```text
--lang=smt2 --full-saturate-quant --quant-ind --conjecture-gen
```

量词归纳 + 猜想生成 + E-matching（默认开）。最通用。

#### `cvc5_inductive_no_ematching`

```text
… --quant-ind --conjecture-gen --no-e-matching
```

`--no-e-matching`：关掉 E-matching，减轻实例化爆炸。提示 LLM 写**更小、对准目标**的重写引理，而不是宽量化猜想。`need_rewrite` / `search_explosion` 会提升它。

#### `cvc4_default`（论文第四路）

```text
--quant-ind --quant-cf --conjecture-gen --full-saturate-quant --lang=smt2.6
```

CVC4 1.6 的归纳配置。有些题 CVC5 证不出、CVC4 能证；无 stats/difficulty，只当证明引擎。

### 8.2 路由增补

#### `adt_structural` — 数据类型结构归纳

```text
--lang=smt2 --full-saturate-quant --quant-ind --dt-stc-ind
```

`--dt-stc-ind`：datatype **structural induction**（按构造子）。纯 ADT 静态首选；`high_difficulty_assertions` 且带 ADT 时也会提升。不默认开 `--conjecture-gen`，枚举更克制。

#### `integer_recursive` — 整数良基归纳

```text
--lang=smt2 --full-saturate-quant --quant-ind --int-wf-ind
```

`--int-wf-ind`：整数 **well-founded induction**。纯 Int 静态首选；`need_arithmetic_lemma` / `need_stronger_lemma` 会提升。

#### `controlled_conjecture` — 限制猜想生成

```text
--lang=smt2 --full-saturate-quant --quant-ind --conjecture-gen
--conjecture-gen-max-depth=2 --conjecture-gen-per-round=5
```

| 选项 | 值 | 讲解 |
|------|----|------|
| `--conjecture-gen-max-depth` | `2` | 猜想项深度上限，避免深层乱枚举。 |
| `--conjecture-gen-per-round` | `5` | 每轮最多 5 条猜想。 |

`search_explosion` / `timeout` 时提升。给 LLM 的含义是：求解器在收窄枚举，引理也要局部。

### 8.3 静态分流 → 候选顺序

| 理论特征 | 候选（先到后） |
|----------|----------------|
| 纯 ADT | `adt_structural`, `cvc5_inductive`, `cvc5_inductive_no_ematching`, `cvc5_simple` |
| 纯 Int | `integer_recursive`, `cvc5_inductive`, `cvc5_simple` |
| ADT+LIA | `cvc5_inductive`, `cvc5_inductive_no_ematching`, `integer_recursive`, `cvc5_simple` |
| 其它 | 论文四路 |

hint：`need_rewrite` → no-ematching / simple；`need_stronger_lemma` → inductive / adt_structural / integer_recursive；爆炸 → controlled_conjecture；高难度 + ADT → adt_structural。

论文四路始终是 fallback。正式 routed run 给 fallback 预留总超时的 **25%** 且至少 **5 秒**。

## 9. 路由与 probe 相关参数

| 环境变量 | 默认 | 讲解 |
|----------|------|------|
| `SOLVER_ROUTING` | `on` | `off` 则完全论文 portfolio，无 top-k、无 probe。 |
| `SOLVER_ROUTING_FALLBACK` | `on` | top-k 失败后再跑论文配置，保护原文已能解的题。 |
| `SOLVER_ROUTING_FALLBACK_FRACTION` | `0.25` | 主 profile 最多用掉 75% 时间。 |
| `SOLVER_ROUTING_FALLBACK_MIN_SECONDS` | `5` | fallback 最少 5s，避免 60s 被主策略吃光。 |
| `SOLVER_ROUTING_TOP_K` | `2` | 正式证明并行的 profile 数。 |
| `SOLVER_ROUTING_PROBES` | `on` | relative 模式是否做短 probe。`llm` 决策器会跳过 probe 排序。 |
| `SOLVER_PROBE_TIMEOUT` | `2` 秒 | 每个候选 profile 的观测时间。不当证明。 |
| `SOLVER_ROUTING_PROBE_MAX_PROFILES` | `3` | 每节点最多 3 个 probe，合计约 ≤6s。 |
| `SOLVER_ROUTING_DECIDER` | `relative` | `relative`：静态+hint+probe 相对分；`llm`：JSON selector，白名单+置信度校验。 |
| `SOLVER_ROUTING_LLM_MIN_CONFIDENCE` | `0.55` | selector 置信度低于此则退回静态序。 |

**Probe utility**（有对照时）：对数相对增益，\(\ln 2\approx 0.693\) 映到约 1 分再封顶。Vampire 认归纳（帽 3）/ 整数归纳（帽 2.5）/ 改写（帽 1.5）；子句涨且无归纳则 −1.5。CVC5 认 skolem（帽 2.5）/ INST / datatype（帽 1.5）；只有 conjecture 且无产出时微加再可能扣爆炸。无对照时**只按 status**（error −20，timeout 小罚），禁用 `gen>2000` 这类绝对爆炸门。timeout 额外 −0.1。

## 10. Hint → prompt 族（不是 profile，但共用同一套 kind）

模板按**文件里教 LLM 写什么**对齐，不按文件夹英文名对调：

| hint 族 | kinds | 倾向的生成模板 | 理由 |
|---------|-------|----------------|------|
| 重写 | `need_rewrite`, `induction_stuck`, `need_directed_rewrite` | `prove_prompt_term_rewrite` | 求解器缺能触发匹配/解调的等式；该模板按目标项做定向重写 |
| 一般化 / 归纳 | `need_induction_lemma`, `need_stronger_lemma`, `need_arithmetic_lemma`, `induction_depth_limit` | `prove_prompt_equational_reasoning` | 求解器缺归纳步上的桥或更强 IH；该模板走等式归纳推理 |

没有 hint：论文顺序（equational → term_rewrite）。两类同时出现：按各 hint 的 `strength`（overshoot）抽样，\(P(\texttt{term\_rewrite})=\texttt{rewrite}/(\texttt{rewrite}+\texttt{generalize})\)，不丢任一模板。连续两次无帮助才切换另一族。`search_explosion` 等只改 profile，不改 prompt 族。

## 11. 一张对照表：同一条 hint 对两边 profile 做什么

| hint | Vampire 提升 | CVC5 提升 |
|------|--------------|-----------|
| `induction_stuck` / `need_rewrite` | `struct_induction`, `induction_portfolio` | `cvc5_inductive_no_ematching`, `cvc5_simple` |
| `need_directed_rewrite` | 同重写族 | 同 `need_rewrite` |
| `need_induction_lemma` / `induction_depth_limit` | `induction_portfolio`, `struct_induction` | （CVC 对应 `need_stronger_lemma`）`cvc5_inductive`, `adt_structural`, `integer_recursive` |
| `need_arithmetic_lemma` | `alasca_arith`, `integer_induction`, `smtcomp` | `integer_recursive` |
| `search_explosion` / `timeout` | 收窄 `struct_induction` / `struct_single` | `controlled_conjecture`, `no_ematching` |
| `high_difficulty_assertions` | （Vampire 无 difficulty） | ADT 时 `adt_structural`, `cvc5_inductive` |

lemma 侧的含义见第 4.5 / 5.4 节：hint 先约束「下一轮写什么公式」，再（若开路由）改「用哪套求解器选项」。
